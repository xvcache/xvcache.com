C:\XVCACHE> type what.txt

The vault stays on disk, under the human's control. The journal sits outside the vault. When you read_note, search_notes or write_note, XVcache appends a sha256-chained JSONL line: fingerprints and metadata, never the note body.

verify_journal returns a one-letter verdict:

  • V — intacte: the file still matches the last journaled fingerprint, and the chain is consistent.
  • X — MODIFIÉE hors XVcache: the file changed outside these tools, or the chain is broken.

That local verdict is tamper-evident, not tamper-proof, and not a qualified timestamp. The independent certifying witness is à venir.

C:\XVCACHE> type why.txt

Most Obsidian MCP servers read and write a vault. XVcache can too, and it can sit beside them. Its job is the proof: V (intact) or X (changed outside XVcache), a sha256-chained JSONL of reads and writes, note body never in the log.

C:\XVCACHE> type install.txt

Published on npm as xvcache-mcp. Node.js 20 or later:

XVCACHE_VAULT=/absolute/path/to/vault npx -y xvcache-mcp

Codex (~/.codex/config.toml or a project .codex/config.toml):

[mcp_servers.xvcache]
command = "npx"
args = ["-y", "xvcache-mcp"]
env = { XVCACHE_VAULT = "/absolute/path/to/vault" }

C:\XVCACHE> type approval.txt

  1. Call get_offer or list_plans.
  2. If you know a volume, call recommend_plan (notes_per_month, certifications_per_month, needs_certified_witness).
  3. Call request_upgrade with the plan id.
  4. Show the JSON to your human and wait for an explicit yes. The stub returns status: "needs_human_approval" and checkout_url: null. The intended path is a Stripe checkout link for a human. Later: x402 / USDC between agents. Neither path is live. Never invent a link or an amount.
